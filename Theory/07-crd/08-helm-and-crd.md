
# 08. CRD and Helm

## 1. Зачем Helm нужен для CRD?

Helm используется для упаковки и установки Kubernetes-приложений.

Многие приложения устанавливают собственные CRD.

Например, Helm Chart может содержать:

- Deployment;
- Service;
- ServiceAccount;
- RBAC;
- CustomResourceDefinition.

Но CRD имеют особое поведение при установке через Helm.

## 2. Где размещают CRD в Helm Chart?

В Helm Chart существует специальная директория:

```text
my-chart/
  Chart.yaml
  values.yaml
  templates/
    deployment.yaml
    service.yaml
  crds/
    database-crd.yaml
```

Манифесты в crds/ обрабатываются Helm отдельно от обычных templates.

## 3. Особенности CRD в Helm

Важно понимать:

1. CRD из crds/ устанавливаются до обычных шаблонов.
2. Helm не обрабатывает их как обычные шаблоны.
3. CRD из crds/ не обновляются обычным helm upgrade.
4. CRD из crds/ не удаляются при обычном удалении Helm release.
5. CRD должны быть корректными Kubernetes-манифестами.

Это сделано в том числе для защиты пользовательских Custom Resources.

Удаление CRD может привести к удалению всех объектов соответствующего типа.

## 4. Почему нельзя бездумно удалять CRD?

Представим, что у нас есть:

```text
Database CRD
   |
   +-- payments-db
   +-- orders-db
   +-- analytics-db
```

Если удалить CRD, Kubernetes удалит соответствующие Custom Resources.

Поэтому CRD — инфраструктурный компонент, требующий отдельного управления жизненным циклом.

## 5. Установка через Helm

Пример:

```bash
helm install database-operator ./database-operator
```

Проверяем:

```bash
kubectl get crd
```

Проверяем release:

```bash
helm list -A
```

## 6. Обновление

Необходимо учитывать, что CRD в специальной директории crds/ не обновляются автоматически обычным helm upgrade.

Поэтому обновление CRD часто выделяют в отдельный управляемый процесс.

Перед изменением CRD необходимо проверить совместимость схемы, версий и существующих объектов.
