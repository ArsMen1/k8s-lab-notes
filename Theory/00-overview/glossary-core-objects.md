# Глоссарий базовых объектов K8s

В этом файле собраны основные сущности Kubernetes. Это фундамент, на который будут ссылаться все остальные заметки.

## 🏗️ 1. Workloads (Рабочие нагрузки)

### Pod (Под)

Самая маленькая единица. «Обертка» для одного или нескольких контейнеров, которые делят сеть (localhost) и диски.

### ReplicaSet (РепликаСет)

Контроллер, который следит за тем, чтобы всегда работало заданное количество копий пода (реплик).

* **Зачем нужен**: Если под падает, ReplicaSet создает новый. Обычно создается автоматически через Deployment.

### Deployment (Деплоймент)

Умная обертка над ReplicaSet для stateless-приложений. Умеет делать **Rolling Update** (обновление без простоя) и **Rollback** (откат версии).

* **Иерархия**: Deployment -> ReplicaSet -> Pods.
* Детали обновлений: [[rolling-update]]
* Детали иерархии: [[deployment-vs-replicaset]]

### StatefulSet (СтейтфулСет)

Аналог Deployment, но для **stateful-приложений** (базы данных, Kafka). Гарантирует стабильные имена подов (`app-0`, `app-1`) и персональные диски для каждого пода, которые переживают перезапуск.

### DaemonSet (ДемонСет)

Гарантирует, что на **каждой** ноде кластера будет запущена копия пода. Используется для системных агентов (сбор логов, мониторинг, сетевые плагины).
* Детали: [[daemonset-explained]]

### Job и CronJob

* **Job**: Одноразовая задача, которая должна успешно завершиться (например, миграция БД).
* **CronJob**: Задача, которая запускается по расписанию (как cron в Linux).

## 🌐 2. Сеть и Сервисы (Networking & Services)

### Service (Сервис)

Стабильный сетевой адрес (IP и DNS-имя) для группы подов. Балансирует трафик.

* **Типы**: `ClusterIP` (внутри кластера), `NodePort` (порт на нодах), `LoadBalancer` (внешний балансировщик).
* Детали: [[why-service]] · [[service-types]]

### Ingress (Ингресс)

Правила маршрутизации HTTP/HTTPS трафика снаружи в сервисы внутри кластера (L7). Позволяет использовать один IP для разных доменов/путей.

### Endpoints (Эндпоинты)

Список реальных IP-адресов подов, которые соответствуют селектору сервиса. Создается автоматически. 

* Детали: [[where-are-endpoints-stored]]

### NetworkPolicy (Сетевые политики)

Фаервол для подов. Описывает, каким подам и по каким портам разрешено общаться друг с другом.

## 💾 3. Конфигурация и Хранилища (Config & Storage)

### ConfigMap (КонфигМап)

Хранит **несекретные** данные конфигурации в виде пар ключ-значение. Может монтироваться в под как переменные окружения или файлы.

* Детали: [[configmap-and-secret]]

### Secret (Секрет)

Хранит **чувствительные** данные (пароли, токены, сертификаты). Данные в etcd хранятся в base64 (не шифруются по умолчанию, но это можно включить).

* Детали: [[configmap-and-secret]]

### Volume (Том)

Директория, доступная контейнерам в поде. Бывает временным (`emptyDir`) или постоянным.

### PersistentVolume (PV)

Ресурс хранилища на уровне кластера (как «кусок диска»). Администратор выделяет его, или он создается динамически.

### PersistentVolumeClaim (PVC)

Запрос пользователя на хранилище («мне нужно 10 ГБ»). Kubernetes ищет подходящий PV и связывает их.

## 🛡️ 4. Безопасность и Организация (Security & Organization)

### Namespace (Пространство имен)

Виртуальный кластер внутри физического. Разделяет ресурсы (например, `prod`, `staging`, `monitoring`).

* Детали: [[namespaces]]

### ServiceAccount (Сервисный аккаунт)

Учетная запись для подов. Нужна, чтобы поды могли аутентифицироваться в API Kubernetes и обращаться к другим ресурсам.

### Role и RoleBinding (Роли и Привязки)

* **Role**: Набор прав (например, «читать поды в namespace X»).
* **RoleBinding**: Связывает Role с пользователем или ServiceAccount (дает права).
* Для прав на весь кластер: **ClusterRole** и **ClusterRoleBinding**.

## ⚙️ 5. Управление кластером (Cluster Management)

### Node (Нода)

Физический или виртуальный сервер в кластере (Worker или Control Plane).

### Label (Метка) и Selector (Селектор)

* **Label**: Пара ключ=значение, которая вешается на объект (например, `app: nginx`).
* **Selector**: Способ фильтрации объектов по меткам. Именно так Service находит свои поды, а Deployment — свои ReplicaSet.
* Детали: [[labels-and-selectors]]

### Annotation (Аннотация)

Похоже на метку, но для служебной информации, которую не нужно использовать для фильтрации (например, «создано через Helm»).

### Taint (Загрязнение) и Toleration (Терпимость)

* **Taint**: Метка на ноде, которая отталкивает поды (например, «не ставь поды без GPU»).
* **Toleration**: Разрешение на поде, которое позволяет ему игнорировать Taint и запуститься на этой ноде.
