# Как работает kubectl (под капотом)

Команда `kubectl` — это просто клиент. Она ничего не делает с контейнерами напрямую. 

## Что происходит, когда вы пишете `kubectl apply -f my-file.yaml`:
1. **Чтение файла**: `kubectl` читает YAML-файл, который вы указали (`-f` значит file).
2. **Парсинг и валидация**: Он переводит YAML в формат JSON (именно в JSON общаются компоненты K8s) и проверяет базовый синтаксис.
3. **Поиск API**: `kubectl` смотрит на поля `apiVersion` и `kind` в вашем файле (например, `apps/v1` и `Deployment`). Он обращается к `kube-apiserver` и спрашивает: "Поддерживаешь ли ты такой тип ресурса?".
4. **Запрос (HTTP)**: `kubectl` берет данные для аутентификации (из файла `~/.kube/config`), формирует HTTPS-запрос и отправляет его на `kube-apiserver`.
5. **Что делает API Server**: 
   * Проверяет права (RBAC).
   * Валидирует манифест (например, правильно ли написаны селекторы).
   * Записывает объект в базу данных `etcd`.
6. **Ответ**: API Server возвращает ответ клиенту (например, `deployment.apps/payments-api created`).

## Ключевое слово: Declarative (Декларативный)
`apply` — это декларативная команда. Вы говорите: "Вот мое *желаемое состояние*". 
* Если объекта нет — он его создаст (`created`).
* Если объект есть, но отличается — он его обновит (`configured`).
* Если объект есть и полностью совпадает — он ничего не сделает (`unchanged`).

Именно поэтому `apply` можно запускать 100 раз подряд, и это не сломает кластер.
