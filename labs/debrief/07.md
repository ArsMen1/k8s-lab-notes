# День 7. Разбор

Поды `checkout` Ready и с нужной меткой. Service с тем же селектором тоже есть. Они лежат в разных namespace: поды в `incidents`, Service в `default`.

Селектор не пересекает границу namespace. `EndpointSlice` для Service `checkout` в `default` не содержит backend-ов, потому что Pod находятся в `incidents`: `kubectl get endpointslices -n default -l kubernetes.io/service-name=checkout`.  `kubectl -n incidents get pods` при этом выглядит здоровым, и от этого переезд особенно противный.

Короткое имя `checkout` из пода в `default` резолвится в ClusterIP сервиса в `default`. Адрес есть, бэкендов за ним нет. Имя `checkout.incidents.svc.<cluster-domain>` сейчас тоже ни при чём: в `incidents` такого Service нет.

Починка: перенеси Service в `namespace: incidents` и удали сироту в default, иначе короткое имя в `default` продолжит указывать в пустоту.

Перед удалением проверь `kubectl config current-context` и `kubectl get svc checkout -n default -o yaml`. Выполняй команду только в disposable-кластере и только если это Service, созданный этим заданием; не удаляй одноимённый чужой объект.

```bash
kubectl delete svc checkout -n default
kubectl apply -f Manifests/incidents/07.yaml
kubectl get endpointslices -n incidents -l kubernetes.io/service-name=checkout -o yaml
```

Перед apply поправь namespace у Service в файле.
